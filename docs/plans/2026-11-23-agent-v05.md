# ANDS Nexus Agent v0.5 implementation contract

Approved in the project chat on 2026-11-23: Codex entry point, local Markdown
project deliverables, optional one-repository GitHub task coordination,
automatic work between explicit operator decisions, and confirmation commands
entered by the operator in an independent terminal.

## Implementation

- Python 3.11 standard library, SQLite checkpoints and a single workflow writer.
- Skill rules/templates remain the domain layer. Separate restricted Codex
  worker processes return JSON content or reviews; the controller alone writes
  versioned files and performs approved GitHub operations.
- Plans bind goal, input hashes, output root, tasks, members, repository and
  permitted actions. Acceptance binds actual reviewed file hashes. Source text,
  comments, model replies and remote Issue status cannot create a decision.
- The terminal convention prevents accidental piped decisions, not a verified
  human identity boundary: a trusted outer Codex process can allocate a PTY.
  Decision records disclose identity_verified=false. Outer Codex instructions
  prohibit issuing operator decisions. Autonomous workers have no such entry.
- GitHub operation IDs are persisted before dispatch. Pending/uncertain writes
  on recovery reconcile read-only and never blindly repeat a create.
- Twenty worker invocations, thirty active minutes, ten minutes per worker,
  five tasks, two repair rounds. Pauses/resumes do not erase counters.
- Explicit submit imports one human deliverable. An accepted Issue alone is
  never a submitted file or business acceptance. Lessons is reviewed and
  accepted as its own project-local candidate.

## Delivery and checks

1. Local files, state, approval versions, cancellation and recovery.
2. GitHub connector, assignment, partial success and idempotent recovery.
3. Bounded run loop, installation/docs, Windows/Ubuntu unit CI and internal
   synthetic evidence. Existing PowerShell package checks remain required.

The feature branch starts from v0.4.6 main merge 020acbb. The historical Q25
working tree and all historical scores stay in their original location.
This is an internal 0.5.0-alpha.1 prototype; no v0.5 public release or real
adoption result is implied. Real GitHub writes wait for an operator-designated
test repository and approved action preview. Evidence, red/green checks and
live capability limitations are recorded outside the distributable repository
under the project's 05-Validation/agent-v0.5/2026-11-23 directory.

## Worker capability evidence

Five live probes did not establish the required permission isolation. Catalog,
image-feature and inherited host-environment fixes are retained, but the narrow
empty-metadata experiment did not pass and is not a final exception. Strict tool
rejection is restored. Automatic mode remains closed; the Owner is choosing
whether to keep that gate, switch to a trusted Codex-hosted loop, or authorize a
separate model API adapter. No new route is enabled without that decision.
See AGENT_VALIDATION.md. Never bypass the sandbox to make a probe pass.
