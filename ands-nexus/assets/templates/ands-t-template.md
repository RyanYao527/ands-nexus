# ANDS-T 任务卡模板

> 使用方式：复制本模板，为一个任务填写完整字段。删除不适用的提示语，但保留字段名。
> 脱敏要求：不要填写真实公司、人员、仓库、域名、IP、凭据或业务敏感数据。

## Task Meta

- Task ID: `[填写任务编号或短标识]`
- Title: `[填写任务标题]`
- Owner: `[填写负责角色，不写真实姓名]`
- Date: `[YYYY-MM-DD]`

## Goal

`[用一句话说明业务目标。说明用户或业务方希望达成什么结果，不写实现细节。]`

## Input

> 来源精度：Owner 提供的值与 Agent 的解释分开记录。输入只给范围时，不得自行增加端点包含/排除、单位、精度或舍入规则，再把新增部分归为 Owner 已提供或已解决。例如“周一 00:00 到下周一 00:00”没有明确端点是否包含；原范围可照录，半开区间只能另列为“Agent 建议，待 Owner 确认”，不能写成已确认的 Constraint 或 Acceptance。Current Artifact 与 Next Prompt 均保留此区分；未知细节不阻止起草。

| 输入项 | 来源 | 说明 |
|---|---|---|
| `[PRD / 需求说明 / 用户反馈 / 设计稿 / API 约束]` | `[脱敏链接或文档名]` | `[说明该输入如何影响任务]` |

## Constraint

- 业务红线：`[例如不可改变现有审批口径、不可影响已发布报表口径]`
- 技术限制：`[例如必须复用现有组件、兼容指定运行环境]`
- 安全限制：`[例如不得处理敏感字段、不得输出原始用户数据]`
- 时间与范围：`[例如本轮只交付最小可验收范围]`

## Output

- 交付物 1：`[例如功能页面、接口变更、配置项、文档、迁移脚本]`
- 交付物 2：`[按需填写]`
- 不交付内容：`[明确本任务不包含的范围]`

## Acceptance

> 只写业务可验证结果。不要写 lint、测试通过、覆盖率、类型检查、代码风格等工程质量项；这些归 Gate 2。

- `[业务方可以直接验证的结果 1]`
- `[业务方可以直接验证的结果 2]`
- `[异常或边界场景下的业务表现]`

常见拆分例：

| 原始表述 | 正确位置 | 原因 |
|---|---|---|
| `lint 通过` | Gate 2 | 机器质量检查，不是业务验收 |
| `单测通过` | Gate 2 | 工程质量证据，不是业务结果 |
| `导出文件字段正确` | Acceptance | 业务方可直接验证的输出 |
| `业务方确认可用` | Gate 3 | 人验收动作，不是任务本身的业务结果 |

## Track

选择一个：`Quick` / `Standard` / `Enterprise`

- Selected Track: `[Quick | Standard | Enterprise]`
- 选择理由：`[用 1-2 句说明风险、影响范围、可回滚性、敏感数据情况]`

## Gate Requirement

| Gate | 是否需要 | 通过标准 | 失败动作 |
|---|---|---|---|
| Gate 1 需求准入 | `[是/否/裁剪]` | `[Goal、Input、Constraint、Acceptance、Track 是否清楚]` | `[退回补充任务卡或升级 Track]` |
| Gate 2 机器质量 | `[是/否/裁剪]` | `[测试、lint、类型检查、构建、安全扫描等机器检查]` | `[修复后重跑，不进入 Gate 3]` |
| Gate 3 人验收 | `[是/否/裁剪]` | `[业务方按 Acceptance 验收通过]` | `[返修任务或重写 Acceptance]` |
| Gate 4 发布审批 | `[是/否/裁剪]` | `[发布说明、回滚方案、灰度或审批条件满足]` | `[暂停发布并补齐发布资产]` |
| Gate 5 复盘审计 | `[是/否/裁剪]` | `[Lessons、指标、知识回写、改进 Issue 完成]` | `[补写复盘或创建后续改进项]` |
